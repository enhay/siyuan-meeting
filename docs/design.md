## 1. 设计原则

1. **录音状态在三处始终一致**。右上角图标、会议页控制区和底部浮条读取同一个录音控制器的状态，任何一处都不自行推算计时或状态。
2. **只展示真实状态**。“已保存”只在数据确实写入磁盘后显示；云端接受了转写任务不等于转写结果已保存；线上模式下电脑声音失败时不悄悄降级。
3. **不打断会议**。浮条不抢焦点，录音过程中不弹模态框；有异常时，浮条和图标切换为警示态，详细说明放在会议页里。
4. **思源原生优先**。正文、转写和纪要都是思源原生块，停用插件后仍可阅读；颜色跟随思源主题变量，只有录音红和错误红固定不变。

## 2. 状态模型

### 2.1 录音状态（活动会议，全客户端唯一）

| 状态 | 进入条件 | 图标 | 浮条 | 会议页控制区 |
|---|---|---|---|---|
| 空闲 | 无活动录音 | 话筒线稿 | 不显示 | 「开始录音」 |
| 准备中 | 点击开始，正在申请权限、打开设备 | 话筒 + 转圈 | 不显示 | 按钮禁用，显示「正在打开麦克风…」 |
| 录音中 | 两路（或单路）都已有真实采样 | 红点脉冲 | 音量棒 + 计时 | 计时、两路音量、暂停、结束 |
| 已暂停 | 用户暂停 | 红点静止 + 暂停角标 | 平线 + 冻结计时 + 「继续」 | 计时冻结，「继续」「结束」 |
| 需要处理 | 某一路断开、无信号、写入失败或空间不足 | 警示三角 | 警示图标，悬停显示原因 | 顶部警示条：原因 + 已保存时长 + 可执行的操作 |
| 正在保存 | 用户结束，正在处理最后一批数据并归档 | 转圈 | 「正在保存…」，所有控件禁用 | 「正在保存…」 |
| 已保存 | 归档完成，资源已关联到文档 | 回到空闲 | 显示「已保存」约 3 秒后隐藏 | 录音段列表新增一条 |
| 保存失败 | 归档失败 | 警示三角，直到用户处理 | 一直显示「保存失败」+「打开会议」 | 失败原因、本地已保存位置、「重试归档」 |
| 中断待恢复 | 启动时发现上次未正常结束的录音 | 警示三角 | 不显示 | 恢复横幅（见 §6.3） |

「需要处理」只是叠加在录音中或已暂停之上的提示：采集如果仍在进行就不停止，计时照常，已保存的数据不丢弃。

### 2.2 转写状态（每个录音段一个）

未转写 → 实时转写中（录音期间）→ 转写中（会后转写）→ 已完成；实时转写留下缺口时为「缺口待补」，补齐后为已完成。任何一步都可能进入「失败」或「未完成」（会后转写请求中途关闭思源或断网），两者都由用户手动重试，重开思源后不自动重新提交。触发规则见计划 D4。

### 2.3 纪要状态（每份纪要）

未生成 → 生成中 → 已生成 →（用户编辑后）已修改；也可能是 AI 未配置或生成失败。

## 3. 右上角入口

- 用 `addTopBar` 注册图标，尺寸和悬停态与思源工具栏的其他按钮一致。图标随状态变化（见 §2.1 表）。录音中的红点沿用 anarlog `RecordingIcon` 的样式：外圈 10px、40% 透明度的红色做 ping 脉冲，内点 8px 实心。
- **点击图标只打开菜单，不开始录音**（计划 D1）。菜单项：
  1. 有活动录音时，第一项是「返回当前会议 · 01:12:03」，右侧显示状态文字（录音中／已暂停／需要处理）。
  2. 「新建会议」。有活动录音时可以新建并编辑笔记，但新会议的开始按钮不可用，并提示「已有会议在录音」。
  3. 「最近会议」：最多 8 条，显示标题和日期，按开始时间倒序；数据来自带会议属性的文档。
  4. 「全部会议…」：用思源搜索打开会议文档列表。
  5. 「设置」。
- 悬停提示与菜单第一项的文字一致。

## 4. 会议页

### 4.1 布局

```
┌────────────────────────────────────────────────────────────────┐
│ [纪要 | 笔记 | 转写]  会议标题    [录音设置] [开始录音 / 暂停 / 结束] │
├────────────────────────────────────────────────────────────────┤
│ 当前视图：纪要原生编辑器 / 笔记原生编辑器 / 音频条与转写列表       │
└────────────────────────────────────────────────────────────────┘
```

- 三个视图共享同一会议，原生会议父文档和转写、纪要子文档关系不变。插件只优化会议场景的呈现，不复制正文。
- 胶囊顺序为「纪要 / 笔记 / 转写」，内容区一次显示一个视图，无右侧辅助区。录音时默认笔记；非录音且有纪要时默认第一份纪要，否则默认笔记。用户主动切换后保留其选择。
- 标题默认为「会议 YYYY-MM-DD HH:mm」，可直接编辑；「在思源文档中打开」打开同一篇原生文档。
- 模式与麦克风选择放在页头「录音设置」中，录音按钮、计时、暂停与结束位于页头。浮条继续保留计时、暂停和打开会议的思源适配。
- 页头下方常显当前录音来源与设备；录音中分别显示麦克风和电脑声音的音量。布局按会议页自身宽度适配思源分屏，次要文档操作可从更多菜单访问。
- 转写视图顶部显示音频播放器与录音段；录音及保存期间隐藏播放器。其他视图不显示播放器，切换离开转写时暂停回听。
- 纪要在当前视图内直接编辑原生文档，每场会议一份；未生成、配置缺失、流式生成和失败状态在同一视图显示。

### 4.2 页头录音操作

**开始前**：

- 显示「开始录音」按钮，按钮左侧是 anarlog 的录音红点（10px 外圈 40% ping + 8px 实心）。样式参照 anarlog 页头的 outline 按钮：胶囊圆角、高 28px、左右内边距 6 / 10px、14px 中等字重。
- 模式切换：「线下（仅麦克风）」或「线上（麦克风 + 电脑声音）」，默认沿用上一次的选择。
- 麦克风下拉框，显示设备名称。
- 选择线上模式时，提示「请使用耳机，避免外放声音被麦克风重复录入」。
- 「试音」（P1）：用户点了之后才短暂打开设备显示音量，离开页面或 10 秒后关闭。点击右上角图标或打开会议页都不会采集声音。

**录音中**：

- 计时使用等宽数字（tabular-nums），不满 1 小时显示 `MM:SS`，满 1 小时显示 `H:MM:SS`。计时只累计实际录音时间，不含暂停。
- 会议页分别显示两路音量，浮条保留合成音量反馈。某一路出错时，会议页显示警示和一句短原因，例如「电脑声音无信号」。
- 操作：「暂停」或「继续」，「结束」。保存中两者都禁用，防止重复结束（计划 D1）。
- 结束时不弹确认框，因为结束后还能补录，误结束的代价很低。

**结束后**：页头换成「补录」按钮，并显示录音段数和总时长。补录会在原会议下新增一个录音段，不覆盖此前的录音（计划 D2）。

### 4.3 转写视图：录音与回听

- 列出本场会议的录音段，例如「录音 1 · 14:30–15:42 · 1:08:12」「补录 2 · 16:05–16:20 · 0:14:50」。每段显示转写状态（§2.2）和「转写」按钮。
- 回听条参照 anarlog `Timeline`：
  - 左侧是 28px 圆形播放／暂停按钮，带边框和卡片底色。
  - 中间是波形，高 24px。
  - 右侧是等宽字体的「当前 / 总长」，以及倍速选择（0.5×–2×，等宽小字）。
  - 右键菜单：播放、停止、在文件夹中显示。删除录音不放进右键菜单，见 §7 的 F-AR-04。
- 回听条位于正文滚动区域之外，阅读长转写时仍可操作。波形支持鼠标定位和键盘调整；转写阅读区支持空格播放／暂停，输入与编辑时不拦截空格。
- 某段录音中途发生过中断或暂停时，在波形上的对应位置标一条细竖线，悬停显示实际时间，例如「14:52 暂停，15:01 继续」。回听时不插入静音（计划 D2）。

### 4.4 转写视图：转写内容

- 转写写入「转写」子文档的思源原生块（§8 的 Q1），录音段的音频块放在文档顶部（Q3）。每个说话段是一个段落块，文本格式为 `[00:12:34] 说话人 1：……`，停用插件后也能读懂。块属性记录录音段编号和段内起始毫秒，用于定位。
- 插件启用时，点击段落里的时间戳会跳转回听到该位置；悬停显示实际时间，例如「14:42:34」。
- 说话人标签按说话人编号着色，配色参照 anarlog `SegmentHeader`，且使用思源主题变量。线上录音按声道标为「我」「其他参会者」，线下录音标为「说话人 N」，不推断身份。点击标签可重命名；操作前展示本场会议的同名标签数量与修改范围，保留原文格式和时间戳。
- 搜索转写正文时高亮匹配，提供上一处／下一处；支持 Ctrl/Cmd+F 聚焦搜索及 Enter／Shift+Enter 定位。播放时高亮当前段落，默认跟随播放；向上阅读会暂停跟随，可用开关恢复。录音期间改为跟随最新转写。
- 「编辑转写」在会议页内打开同一份原生转写文档，完成后刷新阅读视图。录音期间不提供回听与批量改名；转写标签提示实时转写、暂停、处理及需查看的状态，空态根据实际配置与录音状态给出下一步。
- 录音期间，开启实时转写时逐句显示实时转写；实时转写没有进行时，用一行不打断的提示说明原因。
- 会后转写进行中，显示录音段名称和已用时间；有缺口时标出缺口时段，并提供「补齐缺口」。

### 4.5 纪要视图

状态与文案参照 anarlog `Enhanced`：

- **未生成**：居中显示「生成纪要」按钮，下面一行说明「将使用本场笔记与 N 段转写，共约 X 字」。还没有转写时按钮仍可点，说明改为「暂无转写，仅根据笔记生成」。
- **AI 未配置**：说明需要先在思源设置中配置 AI，并给出入口；不显示生成按钮。
- **材料超出容量**：说明材料约 X 字，超过当前模型约 Y 字的上限；提供「只用笔记」「选择录音段」两种缩小范围的方式。不静默截断（计划 D4）。
- **生成中**：先显示一行脉冲文字「正在整理会议内容…」。如果思源 AI 接口支持流式输出，就按 anarlog `StreamingView` 逐字显示；不支持就只显示进度和「取消」。取消后丢弃结果，不写入文档。
- **失败**：显示警示图标、标题「纪要生成失败」、原因，以及「重试」按钮。
- **保存失败**：本页保留已生成结果和生成时确认的原文信息，提供「重试保存」「复制生成结果」「查看纪要文档」。重试不再次调用 AI；内容已经保存、后续信息写入失败时不重复追加；人工修改过原文时停止覆盖。
- **已生成**：纪要是原生块，可以直接编辑。顶部显示「生成于 15:50 · 基于笔记与 2 段转写」和「重新生成」按钮。
- **模板**：会议页使用独立的模板选择与管理组件，设置中复用同一管理组件。内置通用纪要、行动清单、决策记录；可复制为自定义模板，也可新建、编辑与确认删除。模板包含名称、提示词和 Markdown 模板，后两项至少填写一项。自定义模板随当前工作空间的插件数据保存；选择与保存均不自动调用 AI。
- **内容更新**：生成时记录所用模板、笔记、转写及范围的校验信息；相关内容变更只用一行灰字提示重新生成，恢复原内容后解除提示。旧纪要无生成依据时不推断过时。模板被删除时保留纪要，重新选择后才可生成。
- **重新生成**：每场会议只保留一份纪要。先确认；用户改过纪要时，明确提示修改会丢失；确认后原位替换（计划 D7）。

## 5. 底部浮条

### 5.1 尺寸与布局

参照 anarlog 紧凑态，并按本插件的需要补上计时、暂停和「打开会议」：

```
 ┌───────────────────────────────────────┐
 │ ▁▃▅▃▁  01:12:03   ⏸   ↗ │   高 38，圆角 14
 └───────────────────────────────────────┘
          ↑ 悬停时上方出现点阵拖动把手；悬停音量棒切换为「■ 结束」
```

| 项 | 值 | 来源 |
|---|---|---|
| 外边距 inset | 4 | anarlog `FLOATING_BAR_INSET` |
| 紧凑高度 | 38 | `FLOATING_BAR_COMPACT_HEIGHT` |
| 外框圆角 / 控件圆角 | 14 / 10 | `COMPACT_RADIUS` / `CONTROL_RADIUS` |
| 图标按钮 | 30×30 | `COMPACT_ICON_SIZE` |
| 音量棒 | 26×20，棒宽 3，间距 2 | `StopControl` 中的 `DancingSticks` |
| 拖动把手 | 高 12，上留白 7，下间距 2；圆点 0.8px，间距 5×7 | `HoverHandle` |
| 距屏幕底边 | 8 | `SCREEN_MARGIN` |
| 计时 | 12px 等宽数字 | 本插件新增 |

内容从左到右依次是：

- **音量棒／结束**：与 anarlog 的 `StopControl` 合并为一个固定 62 宽的按钮。平时在按钮内显示两路合成的音量棒（26×20，棒宽 3，间距 2），悬停时切换为「■ 结束」并显示 18% 透明度的红色底，点击即结束。音量取 `hypot(mic, speaker)` 并限制在 1 以内，与 anarlog 的批量转写页一致。
- **计时**。
- **暂停／继续**：30 宽的图标按钮。
- **打开会议**：30 宽，切回思源并打开会议页。

总宽度约 200（与 anarlog 相同的 `controls + 4×2 padding + 4×2 inset` 计算方式；计时占 62，容纳 H:MM:SS），以实测为准。不提供 anarlog 的实时字幕展开（计划把实时转写列为不做）。

### 5.2 颜色

颜色跟随思源当前的明暗模式。浮条是独立窗口，由主窗口把明暗模式同步过来。

| 用途 | 浅色 | 深色 |
|---|---|---|
| 底色 | `rgba(219,217,209, 0.82·α)` | `rgba(110,112,102, 0.82·α)` |
| 悬停底色 | `rgba(219,217,209, min(1.08·α, 0.95))` | 同左，换深色 RGB |
| 内容色 | `rgb(31,28,26)` | `#fff` |
| 外描边 0.5px | 内容色 12% | 内容色 14% |
| 控件悬停填充 | 内容色 7% | 内容色 8% |
| 录音红（音量棒、结束） | `rgb(255,51,77)` | 同左 |
| 错误红 | `rgb(255,64,61)` | 同左 |

α 是浮条不透明度，默认 0.9，可设置范围 0.35–0.95。已暂停时音量棒变为内容色的一条平线（`DancingSticks` 在 amplitude 为 0 时就是平线），计时降到 60% 不透明度，以此和录音中区分。

### 5.3 状态表现

- **录音中**：音量棒跳动，计时走动。
- **已暂停**：平线、计时冻结，暂停按钮变为 ▶。
- **需要处理**：结束按钮内的音量棒换成错误红警示圆图标，悬停提示原因，例如「电脑声音已断开，麦克风仍在录音。打开会议查看。」。悬停按钮仍显示「■ 结束」，点击结束并保存；右侧「打开会议」进入会议页处理。
- **正在保存**：整条只显示「正在保存…」，控件全部禁用。
- **已保存**：显示「✓ 已保存」，3 秒后淡出隐藏。
- **保存失败**：显示「保存失败」和「打开会议」，不自动隐藏。

### 5.4 窗口行为

以下 Electron 能力都是候选方案，每一项都要在 Delivery 1 中分别于 macOS 27 和 Windows 11 实测，不能把一个平台的结果外推到另一个平台：

- 不抢焦点：`type: 'panel'`（macOS）、`focusable: false`、`showInactive()`。对应 anarlog 的 `.nonactivatingPanel`。
- 全屏和多桌面下可见：`setAlwaysOnTop(true, 'floating')`、`setVisibleOnAllWorkspaces(true, { visibleOnFullScreen: true })`。对应 `.canJoinAllSpaces` 和 `.fullScreenAuxiliary`。
- 不出现在任务栏和 Dock：`skipTaskbar: true`。
- 共享屏幕时不被采集：`setContentProtection(true)`，对应 anarlog 的 `sharingType = .none`。用户在腾讯会议里共享屏幕时，其他参会者看不到浮条。
- 透明、无边框、无阴影、不可缩放、不可关闭（只能通过结束录音来隐藏）。
- 位置：
  - 默认显示在当前显示器工作区的底部居中。
  - 用户拖动后，本次录音期间记住拖动后的位置；显示器变化时把位置收回工作区内（参照 `frame_at_controls` 的夹取逻辑）。
  - 下一次录音回到默认位置。
- 浮条与主窗口通信：浮条页面放在插件目录内，与思源主窗口同源，优先使用 `BroadcastChannel`。浮条只发送用户的操作意图（暂停、继续、结束、打开会议），状态只由主窗口的录音控制器下发，浮条不保存状态。
- 卸载插件时销毁浮条窗口并移除监听（计划 D1）。

## 6. 异常与恢复的用户表现

### 6.1 开始失败

- **麦克风权限被拒**：说明如何在系统设置中授权，并提供「重试」按钮。
- **线上模式下电脑声音打不开或无采样**：不开始录音，给出原因，提供两个选择：「重试」，或显式点击「改为仅录麦克风」。

### 6.2 录音中出错

- **某一路断开**：
  - 另一路继续录音，浮条和图标进入「需要处理」。
  - 会议页警示条显示「电脑声音 14:52 起中断，麦克风仍在录音」，提供「重新连接」和「结束录音」。
  - 重新连接后，在时间轴上标出这段缺口。
- **长时间无信号**：线上模式下，电脑声音连续 60 秒（可调）没有任何采样时，只提示「电脑声音长时间无信号，请确认会议声音正在播放」。这一条不进入「需要处理」，因为会议中本来就会有沉默。
- **写入失败或空间不足**：进入「需要处理」，显示已保存的时长和本地位置；采集是否继续，取决于是否还能写入。

### 6.3 启动时恢复

发现上次未正常结束的录音时：

- 右上角图标显示警示。
- 会议页顶部显示横幅：「上次录音在 15:31 意外中断，已保存 1:01:12。」提供「保存已录部分」和「稍后处理」。
- 保存后，这段录音和正常录音段一样，可以回听、转写和补录。
- 横幅如实说明中断，不把中断前后拼接成一段连续录音（计划 D2）。

## 7. 功能清单

编号格式为「区域-序号」；后面括号里依次是优先级和所属 Delivery 阶段。P0 是首版必须交付的，P1 是首版可以先不做的。每条后面写的是验收时要观察到的结果。

### 入口与会议管理（ENT）

- **ENT-01** 右上角录音图标，显示五种状态（空闲、录音中、已暂停、需要处理、正在保存）。（P0，D1/D2）
  验收：同一时刻，图标、会议页和浮条显示的状态一致。
- **ENT-02** 点击图标打开菜单：返回当前会议、新建会议、最近会议、全部会议、设置。（P0，D2）
  验收：点击图标本身不会采集声音。
- **ENT-03** 新建会议：创建原生文档并打开会议页，标题默认是日期时间。（P0，D2）
  验收：在普通文档页签中可以看到同一篇文档。
- **ENT-04** 会议文档带有会议属性，用于列出会议和识别会议。（P0，D2）
  验收：重启思源后最近会议仍然完整。
- **ENT-05** 「在思源文档中打开」。（P0，D2）
- **ENT-06** 关闭会议页后重新打开，恢复录音状态和用户选择的视图。（P0，D2）

### 录音（REC）

- **REC-01** 线下和线上两种模式，以及麦克风设备选择；默认沿用上次的选择。（P0，D1/D2）
- **REC-02** 线上模式下两路分别采集、分别显示音量；电脑声音失败时不开始录音，只有用户显式选择后才改为仅麦克风。（P0，D1）
  验收：用耳机播放合成音频时，电脑声音这一路有真实采样。
- **REC-03** 暂停立即停止采集，冻结计时；继续后仍属于同一个录音段。（P0，D1/D2）
- **REC-04** 结束：处理最后一批数据，归档，显示真实的保存状态；保存过程中不能再次结束。（P0，D2）
- **REC-05** 补录：在原会议下新增录音段，不影响已有录音。（P0，D2）
- **REC-06** 同一个客户端同时只能录一场会议；其他会议页的开始按钮不可用并说明原因。（P0，D2）
- **REC-07** 切换文档、关闭会议页都不影响录音。（P0，D1/D2）
- **REC-08** 某一路断开或无采样时提示，并支持重新连接；时间轴标记缺口。（P0，D1/D2）
- **REC-09** 录音时长达到两小时时内存不随时长持续增长。（P0，D1）
  验收：记录两小时录音过程中的内存曲线。
- **REC-10** 试音。（P1）
- **REC-11** 设备热切换，例如录音中插拔耳机。（P0 只要求检测到并提示，自动切换为 P1；D1 验证）

### 浮条（BAR）

- **BAR-01** 录音、暂停、需要处理、保存中、已保存、保存失败六种表现（§5.3）。（P0，D2）
- **BAR-02** 暂停／继续、结束、打开会议三个操作，与会议页走同一个控制器。（P0，D2）
- **BAR-03** 不抢焦点。（P0，D1）
  验收：在腾讯会议中打字时点击浮条，输入焦点不丢失。
- **BAR-04** 切换应用、思源最小化、全屏会议、切换 Mac 桌面、多显示器时仍然可见，且不超出屏幕。（P0，D1）
  验收：两个平台分别记录结果。
- **BAR-05** 拖动移动位置，本次录音内记住位置。（P0，D2）
- **BAR-06** 共享屏幕时不被采集。（P1，D1 验证可行性）
- **BAR-07** 不透明度设置。（P1）

### 保存、归档与恢复（SAV）

- **SAV-01** 录音过程中持续写入磁盘，格式支持从已写入的部分恢复。（P0，D1）
  验收：在录音中强制结束进程，再次启动后能播放强杀之前的内容。
- **SAV-02** 写入失败或空间不足时明确报告，已保存的部分不丢弃。（P0，D1/D2）
- **SAV-03** 结束后以思源资源归档，并关联到会议文档。（P0，D2）
  验收：在另一台设备同步后能看到并播放这段音频。
- **SAV-04** 启动时检查是否有中断的录音，显示恢复横幅（§6.3）。（P0，D1/D2）
- **SAV-05** 进行中的录音只由录制它的设备管理，其他设备只能看到已完成的录音段。（P0，D2）
- **SAV-06** 退出思源或卸载插件时尽量处理最后一批数据，但不把这一步当作唯一的保存方式。（P0，D2）

### 回听（PLY）

- **PLY-01** 录音段列表：时间范围、时长、转写状态。（P0，D2）
- **PLY-02** 回听条：播放／暂停、波形、当前时间与总长、倍速。（P0，D3）
- **PLY-03** 暂停和中断的位置在时间轴上标出，悬停显示实际时间。（P1，D3）

### 转写（ASR）

- **ASR-01** 设置中填写腾讯云 AppId、SecretId、SecretKey；默认不读取任何已有的个人配置。未配置时仅在转写页显示一行灰字和配置入口，不影响录音。（P0，D3）
- **ASR-02** 会后转写一个录音段一次请求，覆盖整段；「结束后自动转写」开关默认关闭，关闭时由用户手动发起。（P0，D3）
- **ASR-03** 转写状态和缺口持久保存在录音段上；请求中途中断后重开思源不自动重新提交。（P0，D3）
  验收：转写请求进行中关闭思源，重开后该段显示未完成，云端调用记录里没有自动发起的第二次请求。
- **ASR-04** 转写结果写成原生块：时间戳、说话人、正文，块属性记录定位信息。（P0，D3）
- **ASR-05** 点击时间戳跳转回听到对应位置。（P0，D3）
- **ASR-06** 失败和未完成可以手动重试；「重新转写」先确认会再次计费，改过的转写会提示修改将丢失。（P0，D3）
- **ASR-07** 说话人重命名。（P1）
- **ASR-08** 线上模式按声道标注「我／其他参会者」。（P0，D3）
- **ASR-09** 实时转写开关，默认开启；断线缺口记录并按计划 D4 补齐，实时转写失败不影响录音。（P0，D4）

### 纪要（SUM）

- **SUM-01** 使用思源配置的 AI 手动生成纪要，输入是所选会议的笔记和转写。（P0，D4）
- **SUM-02** 生成时使用固定的材料快照，生成过程中的编辑不进入本次材料。（P0，D4）
- **SUM-03** 生成前估算材料大小；超出上限时说明原因，并提供缩小范围的方式，不静默截断。（P0，D4）
- **SUM-04** 状态和文案：未生成、AI 未配置、生成中、失败、已生成（§4.5）。（P0，D4）
- **SUM-05** 生成中可以取消，取消后不写入任何内容。（P0，D4）
- **SUM-06** 重新生成：每场一份纪要，确认后原位替换，改过时提示修改将丢失。（P0，D4）
- **SUM-07** 提示词改编自 anarlog 的 enhance 模板，并按计划 D5 修改；保留许可说明。（P0，D4）
- **SUM-08** 第一次开始录音时，保存一份会前笔记快照作为提示词输入。（P0，D2 时保存，D4 时使用）
- **SUM-09** 复用模板管理与选择组件，支持只读内置模板及「提示词 + Markdown 模板」自定义模板；模板和材料变化只显示轻提示，显式重新生成后才应用。（计划 D5/D7）

### 通用（GEN）

- **GEN-01** 颜色使用思源主题变量，跟随明暗模式。（P0）
- **GEN-02** 所有图标按钮都有 aria-label 和悬停提示；在减少动态效果的设置下，音量棒改为静态柱，红点不做脉冲。（P0）
- **GEN-03** 首版界面文案只有中文，但文案集中管理。（P0）
- **GEN-04** 卸载插件时清理浮条窗口、监听和定时器。（P0，D2）

### 明确不做

与计划 Scope 的 Out 一致，另外再明确以下几项：

- 浮条上的实时字幕和 anarlog 浮条的字幕展开态（实时转写只在会议页转写视图显示）。
- 日历倒计时和「加入会议并录音」。
- 会议分享。
- 模板市场和一场会议的多份纪要。
- 自动识别参会者。
- 删除录音的快捷入口（P1：如果要做，必须二次确认）。

## 8. 已确认的数据与安全决定

以下三项影响数据语义或安全，已确认。

- **Q1 转写和纪要的存放位置**：作为会议文档的两个子文档「转写」「纪要」，会议文档本身只放手写笔记。
  - 理由：两小时的转写有两三万字，放进笔记文档会让笔记难以编辑，也会让材料快照的边界不清楚；纪要单独成文，「用户改过没有」才好判断。
- **Q2 腾讯云密钥的存放位置**：只存在本机，不放进插件数据目录，因为那个目录会随思源同步进同步仓库。代价是每台设备需要分别配置。
- **Q3 音频与文档的关联方式**：在「转写」子文档顶部，为每个录音段放一个原生音频块，引用该段的资源文件。这样思源的「清理未引用资源」不会误删音频，停用插件后仍可播放；块属性只用来记录定位信息，不作为唯一的引用。
