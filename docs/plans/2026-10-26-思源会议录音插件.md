# 思源会议录音插件实施计划

## Need

在思源桌面端完成一到两小时会议的录音、手写记录、转写和纪要整理。线下录麦克风，线上同时记录自己的麦克风与电脑播放的其他参会者声音。支持暂停、继续和同场会议补录，用户切换文档或关闭会议页不丢失正在进行的录音。

会议进行中能看到实时转写；会议结束后，不需要把录音暴露到公网，就能得到整场带时间戳、能区分说话人（线上会议区分「我」和「其他参会者」）的转写，再据此整理纪要。界面只用业务语言说明发生了什么、用户能做什么，不出现内部状态名、字段名、接口名或技术参数。

新插件独立于轻墨，轻墨继续保持碎片速记定位。开发目录为 `/Users/zhaohua/code/siyuan-meeting`；目录名不是最终产品名称。产品入口位于思源菜单栏右上角，以录音图标呈现。

## Context

- 交互与视觉设计、细化功能清单，以及转写／纪要子文档、密钥仅存本机、音频块引用三项数据决定见 [design.md](../design.md)；与本计划冲突时以本计划为准。
- 本机思源 3.8.7 安装包与该版本公开源码均显示 Electron 44.7.0；主窗口启用 Node.js 和 `@electron/remote`，Mac 包声明麦克风和系统音频采集用途。源码依据：[package.json](https://github.com/siyuan-note/siyuan/blob/v3.8.7/app/package.json)、[main.js](https://github.com/siyuan-note/siyuan/blob/v3.8.7/app/electron/main.js)。这些证据支持纯插件采集候选方案，不代表已完成实际录音验证。
- Electron 提供系统音频 loopback；Mac 使用 CoreAudio Tap 的路径需要相应系统权限，创建音轨成功不证明实际有采样数据。参考 [Electron desktopCapturer](https://www.electronjs.org/docs/latest/api/desktop-capturer)。Windows 11 与 macOS 27 的实际双路采集、设备切换和长时间稳定性必须在目标设备验证。
- 思源提供 `addTopBar`、`addTab`、`openTab`、`Protyle`。自定义页签内嵌原生编辑器及关闭后重新打开的行为，应以思源 3.8.7 验证结果为准。[官方示例](https://github.com/siyuan-note/plugin-sample/blob/main/src/index.ts)
- 腾讯云异步录音文件识别（[接口文档](https://cloud.tencent.com/document/product/1093/37823)）不适合本插件：直接提交音频上限 5 MB，按本插件的 16 kHz、16 bit WAV 计算，线下单声道约 2 分 44 秒、线上双声道约 1 分 22 秒；更长的录音只能提供公网 URL。文档写明「16k音频仅支持单声道」，双声道只支持 8k 电话音频，因此线上双声道 16k 录音按现有方式提交很可能被拒（未实际调用验证）。思源 S3 同步仓库不等同于转写服务可读取的原始音频地址。
- 腾讯录音文件标准识别通过 URL 支持最长 5 小时、最大 1GB；本地直传的 5MB 上限不用于本插件。采用单声道大模型 2.0 与说话人分离。
- 两小时 16 kHz 单声道 WAV 约 230 MB，可整体提交标准识别；文件超过对应服务大小或时长上限才分段，不压缩。
- 腾讯云实时语音识别（[接口文档](https://cloud.tencent.com/document/product/1093/48982)）为 WebSocket 接口，地址含 AppId，用 SecretId／SecretKey 签名；只接受 16 kHz 或 8 kHz、16 bit 单声道；建议每 200 ms 发送 200 ms 音频，1 秒内发送超过 3 秒音频、两包间隔超过 6 秒或 15 秒未发送音频都会报错断开；文档未提说话人分离；账号默认并发 200。
- 豆包流式语音识别 2.0（[接口文档](https://docs.volcengine.com/docs/DoubaoVoice/bidirectional-streaming-automatic-speech-recognition-websocket?lang=zh)）为 WebSocket 接口 `wss://openspeech.bytedance.com/api/v3/sauc/bigmodel_async`，鉴权只用请求头 `X-Api-Key`、`X-Api-Resource-Id`（按小时计费 `volc.seedasr.sauc.duration`，按并发计费 `volc.seedasr.sauc.concurrent`），文档没有地址参数鉴权，浏览器自带的 WebSocket 加不了请求头。消息为二进制帧包裹的 gzip JSON 与音频；`enable_speaker_info` 配合 `show_utterances` 时每句返回 `speaker_id`，句子带 `definite`、`start_time`、`end_time`。文档未写两包最大间隔、空闲超时和单次连接时长上限。2026-10-26 用用户的 API Key 和系统合成语音实测：按小时计费资源可用，识别正确并返回说话人编号；按并发计费资源返回并发额度不足。Node 24 自带的 WebSocket 能带请求头；在思源的 Electron 主进程中带请求头，或为采集窗口的独立会话补请求头，均未验证。
- 豆包录音文件标准版 2.0 使用音频 URL，支持最大 512 MB、最长 5 小时；使用 COS 私有对象的限时签名链接，不依赖思源同步桶。
- 插件尚未发布（`plugin.json` 无发布地址，`package.json` 为 private），已有会议数据只存在于隔离测试空间。
- anarlog 参考版本固定为 `341ccb3a5636a4e2784a9d4f1177a094d855c1bd`，本地目录 `/Users/zhaohua/code/anarlog`。社区部分采用 MIT，`enterprise/` 为独立商业许可；具体复用文件仍须检查最近的许可证与第三方声明。

## Scope

- In：Windows 11、macOS 27、思源 3.8.7；线下麦克风及线上麦克风与系统音频；长录音、暂停续录、补录、持续保存与已保存内容恢复；会议原生笔记、实时转写与会后转写、回听和 AI 纪要；豆包与腾讯云两家转写服务可选；全部用户可见文案的业务语言核验；桌面与手机导入 M4A、MP3、WAV（包含苹果语音备忘录导出的 M4A），手机简版会议列表、内容查看和回听。
- Out：修改轻墨、手机或浏览器录音、浮条上的实时字幕、本地模型集成、自动参会机器人、日历集成、按会议应用隔离系统音频、自动确认真实参会者身份、模板市场、聊天系统、自动生成纪要、纪要多版本，以及推送、发布、生产部署。不使用腾讯云异步录音文件识别和豆包录音文件识别标准版，不要求用户提供公网音频地址或配置对象存储。不接入豆包按并发计费资源和火山引擎旧版控制台鉴权；不在实时与会后之间混用两家服务，所选服务失败或未配置时不自动改用另一家。

## Binding decisions

### D1 独立会议页与原生内容

菜单栏右上角录音图标提供新建会议、返回当前会议及访问已有会议的入口；有活动录音时持续显示录音或暂停状态。点击图标本身不立即采集声音。

录音期间在屏幕底部显示独立的紧凑浮条，切换到腾讯会议等其他应用后仍可查看和控制录音。浮条显示录音／暂停状态、累计录音时间和音量反馈，提供暂停／继续、结束录音及返回会议页的操作。暂停时保留浮条，结束后展示保存状态，保存失败时保留明确提示。浮条不抢占当前应用的键盘焦点，不承载会议正文或实时转写。

右上角入口、会议页控制和底部浮条读取同一场活动会议的状态，操作由同一录音控制器执行；计时、暂停和错误状态保持一致，保存中不重复执行结束操作。浮条由插件管理，关闭会议页不销毁它，卸载插件时清理窗口与监听。

新建会议创建一篇思源原生文档，并打开独立会议页签。标题默认采用日期时间且可编辑，不要求填写表单后才能开始。会议页页头左侧提供「纪要 / 笔记 / 转写」胶囊切换，右侧提供录音操作，主体一次只显示一个视图。笔记和纪要直接嵌入对应原生文档编辑器，转写视图顶部提供回听；录音或保存期间隐藏回听。首次打开时，录音中的会议默认显示笔记，否则已有纪要时显示第一份纪要，其余显示笔记。提供“在思源文档中打开”。同一份笔记仅保存一套原生块，插件不另建正文副本；已保存的转写与纪要也使用原生内容，停用插件后仍可阅读。

### D2 录音行为

开始前显示麦克风设备及是否同时录电脑声音；线上模式不能在系统音频失败时悄悄降级成仅麦克风。两路分别显示音量及错误状态。

同一客户端同时只录一场会议。暂停立即停止采集、冻结累计录音时间；继续仍属当前录音。结束后完成保存并提供播放、手动转写和补录。补录在原会议中创建新录音段，保留此前录音；暂停时间不作为静音插入回听，但保留实际发生时间及时间轴映射。

录音生命周期独立于页签。切换文档、关闭页签不结束录音。主动结束、退出思源和插件卸载需要处理最后一批数据并呈现真实保存状态；不可依赖退出回调作为唯一保存方式。实际系统睡眠或进程终止不能持续采集，恢复后保留已保存数据并说明中断，不伪造连续录音。

### D3 保存与跨设备边界

录音过程中持续持久保存，内存不随整场录音线性累积；保存格式必须支持验证已写入部分的恢复，不能把 MediaRecorder 输出的任意 Blob 当作独立可播放文件。设备断开、写入失败和空间不足应明确报告，已保存部分不得被丢弃。

进行中的录音及恢复信息由录制设备管理，不通过思源同步抢占或续录另一台设备的活动会话。完成后的音频通过思源资源机制归档并关联会议文档，笔记与完成的资源沿用思源现有同步，不另建笔记同步服务。只使用思源 API 修改文档，不直接写 `.sy` 文件。

### D4 转写

转写使用用户自己的豆包或腾讯云服务。实时与会后识别统一输入单声道：线上录音的麦克风和电脑声音等权混合，原始双声道 WAV 仍由思源保存。不再按音源推断「我／其他参会者」；模型提供说话人编号时显示「说话人 N」，未提供时字幕不加前缀，正文标为「说话人」。已有记录保留原标签。

豆包实时使用流式 2.0，会后使用录音文件标准版 2.0（`volc.seedasr.auc`，submit/query）；腾讯实时保留大模型／通用选择，会后使用 `CreateRecTask` / `DescribeTaskStatus` 与 `16k_zh_en_2.0`。设置不再手填 AppId；腾讯密钥通过 `GetUserAppId` 获取并缓存 AppId，仅供实时连接。密钥只存本机，不同步，不写日志。COS 与腾讯识别使用设置中的腾讯密钥；豆包另填 API Key。COS 只填写一项存储桶默认域名，从地址提取桶名和地域；用户在设置中独立配置，不内置或导入 work-skill 的凭据。

会后识别先将单声道 WAV 上传至私有 COS 对象，通过限时签名 URL 提交；不公开桶、不读取思源同步桶。超过服务文件大小或 5 小时时长上限才分段，不压缩音频。上传与混音流式写盘，内存不随整场录音增长。思源原录音不删除。结果成功保存后删除本次任务创建的 COS 对象；删除失败保留任务及清理入口，重开可继续清理。

本机保存任务号、提交阶段、每部分结果、覆盖前文字指纹和 COS 对象信息。重开后只查询已提交任务及清理，不自动再次提交付费请求。提交响应丢失明确提示状态不确定；任务过期或服务明确失败允许用户重新识别，不伪装成无结果成功。处理中修改转写时保护人工修改。查询结果先保存在本机，再写入思源，避免保存失败导致重复识别。

结束后默认只自动补实时缺口；关闭实时识别时由用户手动识别整段。设置提供「结束后自动补齐缺口」，默认开启并替代旧的自动整段转写开关。手动「识别整段／重新识别整段」始终覆盖当前选中段，成功前保留旧文字。重启恢复、继续查询和重试清理不新建识别任务。计费说明集中放设置页，覆盖确认保留人工修改丢失提示。

实时识别失败不影响录音。确定句子约每 10 秒写入原生转写文档，临时文字只供字幕。暂停关闭识别连接，恢复重连；缺口统一为混音时间段。说话人编号仅在一次识别会话内有效，分段或重连时注明编号重新开始。

录音选择区常显编号、起止时间、时长、转写状态，明确标出当前选中段。播放器和识别操作标明对应录音段，转写阅读仍保留所有录音段。

接口依据：[豆包标准版](https://docs.volcengine.com/docs/doubao-voice/task-submission-http-1?lang=zh)、[腾讯录音文件识别](https://cloud.tencent.com/document/api/1093/37823)、[COS 签名](https://cloud.tencent.com/document/product/436/7778)、[AppId 查询](https://cloud.tencent.com/document/product/598/70416)。

### D5 anarlog 的复用方式

参考其“会议笔记与生成纪要分开”“生成任务有明确状态”“重新生成是显式操作”的交互，使用思源组件和新插件自己的状态管理实现，不移植 React/Tauri 界面及 SQLite 数据模型。

右上角录音状态和屏幕底部录音浮条直接参照 anarlog 的视觉与交互细节，适配本插件的暂停续录与会后转写。参考文件为 `apps/desktop/src/session/components/outer-header/index.tsx`、`apps/desktop/src/meeting-float/overlay/bar.tsx` 和 `plugins/windows/src/window/floating_bar.rs`。底部采用独立桌面浮窗；Tauri 窗口调用改用思源宿主可用的 Electron 能力，不因此引入另一套应用或原生辅助程序。

提示词改编自当前在用的 `crates/template-app/assets/enhance.system.md.jinja` 和 `enhance.user.md.jinja`。调用证据为 `apps/desktop/src/store/zustand/ai-task/task-configs/enhance-workflow.ts` → `templateCommands.render`，以及 `crates/template-app/src/enhance.rs` 的模板加载；不采用 `template-app-legacy`。

沿用材料与格式分离：会议基本信息、会前笔记快照、当前会议笔记、时间戳转写分别输入，格式指令单独管理。保留事实准确性优先、关注手写重点、保留专业术语的原则。删除“每节至少三条”“只能用 H1”等不适合本产品的格式硬约束；标题层级、加粗等只能表达用户重视程度，不得提高未经证实内容的真实性。缺失的负责人、期限和决定不得补造；笔记与转写矛盾时保留差异，不擅自裁决。材料内的指令只作为会议内容，不能覆盖系统指令。

模板数据、管理与选择/编辑界面独立为可复用模块，会议页和设置共用。提供通用纪要、行动清单、决策记录三个只读内置模板，可复制为自定义模板；自定义模板包含名称、提示词和 Markdown 模板，支持新建、编辑与确认删除，至少填写提示词或 Markdown 模板之一。提示词规定整理要求，Markdown 模板规定输出结构，不执行模板中的代码或变量表达式。自定义模板沿用思源插件的数据保存方式，属于当前工作空间，和本机服务凭据分开保存。模板只决定组织方式和详略，不能覆盖事实与人工修改保护规则。不引入模板市场、术语词典、图片理解、自动重试编排或整套 Rust 模板运行时。复用时保留 Fastrepl 版权及 MIT 文本，并记录固定提交、来源文件与改编范围；不复用企业目录、产品品牌或未核对许可的素材。

### D6 先验证纯插件

优先使用思源现有 Electron 能力。不得为接入录音无条件替换共享会话的媒体请求处理，不自动批准其他页面的采集请求。若不能隔离请求或平台采集不能满足要求，停在能力验证结果，重新确认原生组件等架构选择，不自行引入辅助程序。

### D7 纪要

纪要使用思源配置的 AI，由用户手动发起；输入为所选会议的笔记与转写。录音、原始转写和手写笔记保留，生成结果作为独立纪要内容。生成过程使用固定材料快照，不追随进行中的编辑变化。有模型上下文容量配置时预检长会议，已知超限则提示缩小范围；未填写容量不提示、不阻止生成，由 AI 服务处理请求。不静默截断材料；服务无法处理时明确说明原因。生成前列出尚未转写或缺口尚未补齐的录音段，让用户知道哪些内容不会进入纪要。

每场会议只保留一份纪要。重新生成先确认；用户改过纪要时，明确提示修改会丢失；确认后原位替换。测试空间中已有的多版本纪要不迁移。

每场会议保存所选模板；选择或保存模板不立即调用 AI。删除自定义模板不删除既有纪要；引用已删除模板的会议需重新选择模板后才能生成，不静默改用其他模板。生成时固定模板的提示词和 Markdown 结构、所选范围、笔记和转写，并将这些实际输入的校验信息随纪要保存。模板、笔记或已纳入范围的转写变化时，仅在纪要内显示一行轻提示和重新生成入口；恢复为原内容时解除提示。生成期间出现的新变化不进入本次结果，保存后仍提示更新。旧纪要没有生成依据时不凭空标记为过时。手工修改纪要本身不作为材料更新。

### D8 用户可见文案

会议页、浮条、右上角菜单、设置、提示消息、写进原生文档的文字，以及集市中显示的使用说明，只陈述业务事实：发生了什么、影响什么、用户能做什么。不出现内部阶段或状态名、字段与块属性名、接口与参数名、错误码，以及采样参数、编码、文件头、任务编号之类的实现术语，也不解释实现过程。腾讯云和 AI 服务返回的错误要翻译成业务说明与可执行的操作。唯一例外是设置中的 API Key、SecretId、SecretKey、COS 存储桶地址，因为用户要按火山引擎和腾讯云控制台的同名字段去复制。

核验方式：每个交付切片都审查自己新增或修改的文案；收尾时再对全部用户可见文案和使用说明逐条审查，发现的问题修完才算验收。

### D9 会议页操作与反馈

纪要生成完成后保留本次结果及原文校验信息，保存失败可单独重试保存，不再次调用 AI；原文在此期间发生修改时继续保留人工修改，提供检查原文和复制生成结果的入口。

转写页支持内容搜索、匹配定位、段落级播放高亮、可关闭的播放跟随，以及实时转写跟随。用户主动向上阅读时停止自动滚动，可显式返回最新内容。播放器固定在转写阅读区上方；录音及保存期间仍隐藏。空态和标签如实区分等待首句、暂停、未开启、未配置与失败。

转写纠错使用会议页内的思源原生编辑器，完成后刷新阅读视图；不复制一套可编辑正文。说话人改名更新本场会议中相同标签，操作前说明范围，保留原始时间戳、正文格式和其他属性，不自动推断身份。

录音卡片的选择与内部动作分别支持键盘操作。会议页按自身容器宽度适配分屏，开始前展示当前来源与设备，录音时分别显示麦克风和电脑声音的真实音量。语义颜色适配思源明暗主题。

模板与材料更新、腾讯云未配置等非故障提示使用无警告图标、无色块边框的一行灰字及操作链接，同一页面去重，不弹窗或反复通知。录音中断、归档失败和覆盖人工编辑的确认保留明确反馈。设备偏好写入现有录音控制器的本机工作空间配置目录；首次载入合并已有浏览器偏好后保存并移除旧键，密钥继续只放思源本机 Secrets。腾讯云配置从用户指定来源读取，仅修改本机配置，不在源码或产物中保存凭据。

### D8 已有录音与手机简版

桌面与手机均可将单个 M4A、MP3、WAV 文件添加至当前会议，或新建会议后导入；苹果语音备忘录导出的 M4A 是必需场景。原文件作为思源附件保留，沿用会议及录音块属性，桌面同步后可手动转写并生成纪要。导入不自动调用收费服务。导入文件的原始格式及来源须保存，不能假称为插件采集的 16 kHz WAV。

手机独立加载轻量入口，不加载 Electron、Node 文件系统、桌面录音控制器或云服务凭据。简版提供会议列表、新建、录音导入、回听，以及通过原生文档查看笔记、转写和纪要；不提供现场录音、手机转写或生成纪要。手机会议页固定「笔记 / 转写 / 纪要」三个标签，嵌入原生只读阅读区，分别保留阅读位置；切换不关闭会议页、不打断独立回听。需要编辑时使用思源官方移动端文档入口，不创建第二份正文。

导入文件按服务支持的原格式提交，避免整场解码占用内存；原有采集 WAV 继续单声道分段流程。导入文件超过所选服务文件大小或五小时时长限制时，明确提示先分割文件，原附件保留。沿用私有 COS、任务恢复和成功保存后清理，不改变已有人工修改保护。

验证覆盖不带 Node/Electron 的移动入口、导入后读回的录音属性、M4A 容器时长、转写服务收到的格式及任务恢复。执行语法检查、构建和既有测试；手机文件选择、回听和原生文档视觉验收由用户在设备上完成，不运行浏览器或真实计费调用。

### D9 会议目录与文档导航

新会议放在所选笔记本根目录的「会议」文档下，复用同名目录；不增加年月层级，不自动移动已有会议。会议正文继续承载笔记，转写与纪要仍为直接子文档，不新建独立「笔记」子文档。

新会议及以后新建的子文档补充双向原生链接：会议正文链接到已经创建的转写、纪要，子文档链接回会议。链接使用文档 ID，不依赖标题或目录路径。导航块单独标记，不计入会前笔记、AI 材料或纪要内容指纹；重写纪要保留导航块。已有会议不批量迁移或补写。
