# Windows 录音验证

这是 Delivery 1 的最小验证插件，不是完整会议产品。当前只验 Windows；macOS 按本轮用户决定暂不处理。会议文档、转写、纪要及正式归档需在真实采集验证通过后继续。

## 运行

无需安装依赖。使用 `node --run check` 与 `node --run test` 检查代码。将 `index.js`、`plugin.json`、`probe/` 与本说明（保留 `docs/reports/windows-probe.md` 路径）放在**空白测试空间**的 `data/plugins/siyuan-meeting/`，在思源插件设置中启用。右上角话筒菜单打开验证窗口；打开窗口不会自动录音。

本轮测试空间：`C:\code\github\siyuan-meeting\.scratch\workspace`，独立端口 `16808`。不操作日常工作空间。

录音写入 Electron `userData/meeting-probe-continuous/`，不放进思源同步目录。一个录音段持续追加到同一个 PCM WAV，每秒 `fsync`；时间映射追加到 `timeline.jsonl`，录音状态保存在 `recording.json`。双路左声道是麦克风、右声道是电脑声音。停止时补齐 WAV 文件头；意外中断后按实际落盘长度修复文件头，不依赖退出回调。停止只完成本机保存，尚未归档为思源资源。

最初的分秒文件试录仍保留在 `userData/meeting-probe/`，不会覆盖或删除。此次持续追加验证使用单独目录。

## 实机验收

1. 戴耳机播放合成声音，对麦克风试音。选择线上模式开始，确认两个音量表均有信号。15 秒内未观察到非零采样则停止，不能认定采集成功。结束后分别听左右声道，确认没有依赖外放串音。
2. 暂停后检查系统麦克风占用释放、计时冻结；从控制窗和浮条分别继续，确认没有插入暂停静音。关闭验证窗口后录音继续，话筒菜单可重新打开。
3. 切换应用、最小化思源、全屏会议、切换显示器，确认浮条可见且操作不抢键盘焦点；检查拖动和显示器变化后的边界。窗口置顶标志不是实测结果。
4. 录制两小时，观察进程内存与两路回听结果。拔掉设备时确认明确提示。仅杀死隔离空间对应的采集渲染进程，重开验证窗口后检查已保存片段；不要结束共享的日常思源主进程。
5. 测试磁盘写入失败，确认停止采集并保留此前片段；停止／卸载后检查麦克风占用与浮条清理。
