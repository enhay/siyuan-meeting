# 会议录音插件使用说明

本插件在思源桌面端完成会议录音、回听、转写和纪要整理。当前版本按本轮范围只验证 Windows 11，macOS 尚未处理；界面与交互参考 anarlog（固定提交 `341ccb3a5636a4e2784a9d4f1177a094d855c1bd`）的桌面端细节，排版尺寸尽量贴近其页头、视图切换、回听条和底部浮条。

## 安装

1. 将本目录放进工作空间的 `data/plugins/siyuan-meeting/`，或在思源“集市 → 已下载”中启用本地插件。
2. 插件要求思源 3.8.7 或更高版本，并且只在 Windows 桌面端加载。
3. 启用后，右上角工具栏出现话筒图标。**点击图标只打开菜单，不会采集声音。**
4. 更新插件文件后，在思源中禁用再启用插件（或重新加载界面）以刷新 `index.css`。
5. 修改 `src/` 下的源码后先运行 `node tools/build.cjs` 重新生成根目录 `index.js` 和 `index.css`；思源加载这两个入口文件。`capture/` 和 `float/` 是独立的本地页面，不需要打包；但 `capture/storage.cjs` 也被主进程的恢复逻辑使用，修改后同样要重新生成。

测试工作空间为 `.scratch/workspace`，不会操作日常笔记。测试插件目录为
`.scratch/workspace/data/plugins/siyuan-meeting/`。

## 功能

### 右上角入口

- 空闲：话筒线稿。
- 录音中：红点脉冲，悬停显示“录音中 · 时间”。
- 已暂停：红点静止。
- 需要处理 / 保存失败：警示图标。
- 正在保存：转圈角标。

点击图标打开菜单：返回当前会议、新建会议、最近会议（最多 8 条）、全部会议、设置。

### 会议页

- 标题默认“会议 YYYY-MM-DD HH:mm”，点击即可编辑，与原生文档标题同步。
- “在思源文档中打开”用普通文档页签打开同一篇文档。
- 顶部录音控制条：
  - 线下（仅麦克风）/ 线上（麦克风 + 电脑声音）。
  - 麦克风设备选择和刷新。
  - 开始 / 暂停 / 继续 / 结束。保存中禁用重复结束。
  - 两路音量棒；某一路断开时该路显示警示和短原因。
  - 计时只累计实际录音时间，不含暂停。
  - 系统睡眠时请求暂停并保留已写入内容；恢复后提示检查设备，不把睡眠期间拼接成连续录音。
- 页头左侧按「纪要 / 笔记 / 转写」切换，内容区一次显示一个视图。录音操作在页头右侧，模式和麦克风在「录音设置」中选择。
- **笔记**：同一篇会议原生文档，可直接编辑。切换视图或关闭会议页签不会结束录音。
- **纪要**：直接编辑原生纪要子文档，支持版本切换、生成、流式预览、取消和失败重试。重生成保留已编辑版本。
- **转写**：顶部为回听条和录音段，下面显示说话人与时间戳；点击时间戳可定位。录音及保存时隐藏回听，离开转写视图时暂停播放。
- 首次打开时，录音中的会议默认显示笔记，否则有纪要就显示第一份纪要；主动切换后保留选择。

### 底部浮条

录音中显示独立桌面浮窗：

- 音量棒、计时、暂停/继续、结束、打开会议。
- 不抢焦点；切换应用、最小化思源时仍可操作。
- 悬停时上方出现点阵拖动把手，本次录音期间记住位置；下一次录音回到默认位置。
- 明暗模式和透明度跟随设置。
- 保存中只显示“正在保存…”，已保存显示“✓ 已保存”并在约 3 秒后隐藏，保存失败保留“保存失败”和“打开会议”。

### 新建会议的数据

- 会议文档：原生文档，块属性记录 `custom-meeting-id`、`custom-meeting-started`（创建时间）、`custom-meeting-first-recorded`（首次真正开始录音的时间）、`custom-meeting-status`、`custom-meeting-mode`、`custom-meeting-segments`、`custom-meeting-pre-notes`。
- 转写子文档：首次归档录音时创建；顶部放每段录音的原生音频块（`<audio>` 引用思源资源），音频块属性记录录音段编号、时长、采样率、声道、暂停/中断事件、是否中断恢复和转写任务编号。
- 转写正文：每句一个原生段落，格式 `[HH:MM:SS] 说话人 N：正文`，块属性记录录音段编号、段内起止毫秒和说话人编号；停用插件后仍可阅读。
- 纪要子文档：生成时创建；块属性记录生成时间、材料范围和生成内容的指纹。用户改过纪要后再次生成会另存为“纪要（第 2 版）”等新版本，旧版保留。
- 音频：停止后通过 `/api/asset/insertLocalAssets` 归档为思源资源，并引用在转写子文档中，避免“清理未引用资源”误删。
- 正在录制的 PCM WAV 持续写入 Electron `userData/siyuan-meeting/<工作空间哈希>/recordings/<meetingId>/<recordingId>/`，每秒 `fsync`；`recording.json` 记录阶段和事件，`peaks.json` 保存降采样波形。强杀进程后可按实际落盘长度修复 WAV 文件头并恢复。
- 采集诊断：打开音频设备时在会议录音根目录写 `host.json`（Electron/Node 版本、平台、采样率、设备与 Worklet 支持），不包含音频内容。

## 配置

### 腾讯云录音文件识别

密钥只写入思源“设置 → 密钥和变量”，不进入会随思源同步的插件数据目录。插件设置中填写：

- SecretId / SecretKey：留空表示不修改已保存值。
- 公网音频前缀：腾讯云长音频需要一个可访问的 URL。若音频超过 5 MB，请填写能把思源 `assets` 目录映射到公网的地址前缀，例如 `https://media.example.com`。留空时只尝试 5 MB 以内的 base64 直传。
- 识别引擎：`16k_zh` 或 `8k_zh`；插件会按录音采样率选择兼容值。

录音以 16 kHz、16 bit WAV 采集（线上模式为双声道：左麦克风、右电脑声音）。腾讯云任务编号、状态和错误会持久化在音频块属性中；重开思源后继续查询已有任务，不自动重复提交计费任务。

### AI 纪要

纪要使用思源设置中的 AI 模型（编辑模型，未设置时回退到智能体模型）。插件支持 OpenAI Chat Completions、Anthropic Messages 和 OpenAI Responses 三种协议，流式输出；使用 SiYuan 中已配置的 provider，不保存模型密钥。使用 SiYuan 官方 ChatGPT 类型账号时走内核接口，并会先清空编辑器的 AI 对话上下文，避免纪要继承无关对话。

提示词改编自 anarlog 的 `enhance.system.md.jinja`、`enhance.user.md.jinja`、`enhance.format.md.jinja` 和 `summary-length.ts`，按实施计划 D5 修改：

- 保留 Fastrepl 版权和 MIT 文本（见 `src/prompts.js` 文件头）。
- 材料与格式分离：会议信息、会前笔记快照、当前笔记、时间戳转写分别输入。
- 删除“每节至少三条”“只能使用 H1”等硬约束。
- 标题层级和加粗只表达用户重视程度，不提高未经证实内容的真实性。
- 不补造负责人、期限和决定；笔记与转写矛盾时保留差异；材料中的指令不能覆盖系统指令。

## 已知限制

- 只支持 Windows 桌面端。
- 不做实时转写、自动参会机器人、日历集成、模板市场、参会者身份推断。
- 转写首版需要用户自己的腾讯云配置；超过 5 MB 的音频需要可访问的公网地址。
- 说话人重命名、线上双声道“我/其他参会者”标注尚未实现。
- 录音中拔出设备会提示并可重新连接，但不做自动切换设备。
- 纪要预览是插件内的轻量 Markdown 渲染；完整编辑请在原生纪要子文档中完成。
- 界面文案目前写在界面与控制模块中，尚未抽成独立文案表；首版仍只有中文。
- 波形峰值保存在录制设备本机；其他设备同步后可以播放录音，但波形显示为平线。
